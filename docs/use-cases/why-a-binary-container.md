# Why a binary container

- **Prices and quantities are exact.** A price or a quantity is a [64-bit integer scaled by 10⁹](../specification/data-types-and-conventions.md#decimal-values-and-null-values): 177.03 is stored as `177030000000`. A sum, a comparison or an average gives the same result in every language, with no floating-point rounding.
- **Timestamps have nanosecond resolution.** Every record carries the [event time and the receive time](../specification/data-types-and-conventions.md#time) as nanoseconds since 1970-01-01 UTC, so two events inside the same microsecond keep distinct times.
- **One file describes itself.** A container holds reference data and market events together, and the definition of an instrument precedes its trades and quotes. The [`MANIFEST`](../specification/metadata.md#manifest) names the dataset, the publishers and the record types, and the [`PROVENANCE`](../specification/metadata.md#provenance) records the source of the data and the rules of its conversion.
- **Every frame has a checksum.** A [CRC-32C](../specification/compression-and-integrity.md#crc-32c) protects the container header, the metadata, each frame header and each frame payload. A reader checks a frame before it uses any of its records, so damaged or missing bytes are reported and never decoded as data.
- **Compression is optional and per frame.** Each `DATA` frame is stored raw or as one [Zstandard](https://github.com/facebook/zstd) frame, and a reader decodes it without the frames around it. [Compression and integrity](../specification/compression-and-integrity.md) gives the rules.
- **A reader opens only the frames it needs.** The [`INDEX`](../specification/frames.md#index-frames) gives the time range of every frame, and [`FRAME_SUMMARY`](../records/FRAME_SUMMARY.md) records add its record types and its range of instrument IDs. A query reads the frames that can hold a match and skips the rest.
